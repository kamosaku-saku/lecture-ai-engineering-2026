# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
第1回の素のLLMは、基本的にモデル自身が持つ知識をもとに回答していた。一方、第3回のエージェントは、用語集を検索するツールを利用して情報を取得し、その結果をもとに回答できる。

今回「LoRAとQLoRAの違いは？」と質問したところ、エージェントは用語集から両者の定義を取得し、その違いを説明した。また、関連する講義回として第2回を示した。

これにより、エージェントはモデル単体で回答するだけでなく、外部の情報を参照して回答できることが分かった。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
「LoRAとQLoRAの違いは？」という質問に対して、以下の2回のツール呼び出しが確認できた。

search_glossary({'query': 'LoRA'})
search_glossary({'query': 'QLoRA'})

それぞれの検索結果には、用語の定義と関連する講義回の情報が含まれていた。

- 1つの質問での LLM 呼び出し回数（`requests`）：
「LoRAとQLoRAの違いは？」に対して、LLMの呼び出し回数は2回（requests=2）、ツールの呼び出し回数は2回（tool_calls=2）だった。

1つの質問に回答するために、LLMがツールを呼び出し、その結果を受け取ってから回答を生成していることを確認できた。

- 追加したツールと、docstring に書いた説明：
make_quiz という確認問題を作成するツールを追加した。

このツールは、指定された講義回の用語集からランダムに1つの用語を選び、その意味を問う確認問題と答えを返すものである。

docstringには、指定した回の用語から確認問題と答えを作成することや、復習用の問題を求められたときに使用することを説明した。

実際に以下の質問を実行した。

uv run python -m app.agent --trace "第2回の内容から確認問題を1問出して"

その結果、以下のツール呼び出しが確認できた。

make_quiz({'lecture': 2})

ツールからは「事前学習」の意味を問う問題と、その正解が返された。

エージェントの最終回答では、次の確認問題が出題された。

【問題】
「事前学習」の意味は？

正解はツールから取得されていたが、エージェントは問題だけを提示し、利用者が自分で考えられるようにしていた。

このときのLLM呼び出し回数は2回（requests=2）、ツール呼び出し回数は1回（tool_calls=1）だった。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
app/agent.py の INSTRUCTIONS に記載されていた、以下の指示を削除した。

用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。

指示文の変更によってエージェントの動作がどのように変わるかを確認するため、変更前と変更後で同じ質問「LoRAとQLoRAの違いは？」を実行した。

どちらも --trace オプションを使用し、ツールの呼び出し方、LLMの呼び出し回数、回答内容、トークン数を比較した。

使用モデルは両方とも gemini-3.5-flash-lite である。

- 結果：
【変更前】

使用ツール：search_glossary

ツール呼び出し回数：2回

LLM呼び出し回数：2回

入力トークン数：1,196

出力トークン数：179

ツール呼び出しは以下のとおりだった。

search_glossary({'query': 'LoRA'})
search_glossary({'query': 'QLoRA'})

回答では、LoRAとQLoRAについて用語集の定義に沿った説明が行われ、関連する講義回として第2回が示された。

【変更後】

使用ツール：search_glossary

ツール呼び出し回数：2回

LLM呼び出し回数：2回

入力トークン数：1,148

出力トークン数：195

ツール呼び出しは以下のとおりだった。

search_glossary({'query': 'LoRA'})
search_glossary({'query': 'QLoRA'})

回答では、LoRAとQLoRAの違いを最初に要約し、QLoRAによるGPUメモリの節約について説明していた。

【比較結果】

変更前後で search_glossary の呼び出し回数はどちらも2回、LLMの呼び出し回数もどちらも2回だった。また、検索に使用した引数も同じだった。

一方、入力トークン数は1,196から1,148に減少し、出力トークン数は179から195に増加した。

回答内容については、どちらもLoRAとQLoRAの違いを適切に説明していたが、文章の構成や表現に違いが見られた。

以上から、今回の実験では、検索を必須とする指示を削除してもツールの使い方に明確な変化は見られなかったが、回答の表現やトークン数には違いが確認できた。

- 気づき・疑問：
今回の実験を通して、エージェントの指示文を変更しても、必ずしもツールの使用方法が変わるわけではないことが分かった。

検索を必須とする指示を削除しても、エージェントは自ら search_glossary を呼び出していた。このことから、明示的な指示がなくても、モデルが質問内容やツールの説明文をもとに、検索が必要だと判断した可能性があると考えられる。

また、ツールの呼び出し方が同じでも、回答の文章やトークン数には違いが生じていた。ただし、LLMの出力にはばらつきがあるため、この違いが指示文の変更だけによるものかは、今回の1回ずつの比較では判断できない。

さらに、make_quiz の実行では、ツールから問題と答えの両方が返されていたにもかかわらず、エージェントは問題だけを出題していた。これは、エージェントがツールの結果をそのまま表示するのではなく、利用者の質問に合わせて最終的な回答を作成している例だと考えられる。

今後は、同じ条件で複数回実行したり、ツールのdocstringを変更したりすることで、ツールの選択や回答内容にどの程度影響があるのかを検証してみたい。
